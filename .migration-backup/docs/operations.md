# GO COURSE — التشغيل وحدود النسخة الأولى

## الإعداد

1. في Render، اضبط `ADMIN_INITIAL_PASSWORD` سرًا بطول 12 حرفًا أو أكثر ثم أعد تشغيل الخدمة.
2. سجّل الدخول بالبريد `gocourse1@gmail.com`، وغيّر كلمة المرور المؤقتة عند أول دخول.
3. أنشئ الأستاذ أولًا وحدّد لغاته ومستويات كل لغة.
4. أنشئ دورة وحدّد اللغة ونوعها ومستواها والأستاذ والنظام والحصص الأسبوعية والإجمالي والجدول. انشر الدورة.
5. أنشئ الباقات واربطها بالدورات.
6. أنشئ الطالب وبياناته الأكاديمية وارفع وصل الدفع؛ يمكن إضافته إلى دورة وقت إنشائها أو لاحقًا.
7. راجع طلب الدفع اليدوي؛ التأكيد ينشئ اشتراكًا وفاتورة مرة واحدة.
8. ينشئ المدير حساب الأستاذ أو الطالب بكلمة مرور مؤقتة، ويسلّم بيانات الدخول لصاحب الحساب. يُطلب تغيير كلمة المرور عند الدخول أول مرة.

لا يوجد تسجيل ذاتي. كلمات المرور تُخزّن مشفّرة، والجلسات مرتبطة بحساب Neon؛ يستخدم الجميع رابط الدخول نفسه.

## مفاتيح التشغيل

تستخدم الخدمات متغيرات المصادقة والتخزين وقاعدة البيانات المضبوطة في إعدادات المشروع. لا تُنسخ قيمها إلى الملفات أو المحادثة.

المتغير السري الإضافي على Render: `ADMIN_INITIAL_PASSWORD`. لا تضف كلمة المرور أو رابط Neon إلى Vercel.

أوامر الفحص:

```sh
pnpm run typecheck
pnpm --filter @workspace/api-server test
pnpm --filter @workspace/api-spec run codegen
```

## البيانات والترحيلات

لا توجد بيانات أعمال تجريبية؛ اللغات والمستويات فقط إعدادات أولية.
البيانات في PostgreSQL وليس في localStorage. في إعداد Render المقترح تُحفظ الملفات الخاصة نفسها داخل Neon، وفي المعاينة الحالية يبقى التخزين الخاص السابق متاحًا.
الأرشفة لا تحذف التاريخ. العلاقات محمية بمفاتيح خارجية وقيود فريدة.

مخطط النسخة الأولى:

- `school_users`: الهويات والأدوار والصلاحيات.
- `school_records`: سجلات المجالات التعليمية والمالية والمحتوى والإشعارات والتدقيق.
- `school_links`: علاقات منظّمة ومحمية بالمفاتيح الخارجية.
- `teacher_specialties`: الأستاذ واللغة والمستوى.
- `school_files`: ملكية الملف ومرجعه وحجمه ونوعه والدورة.
- `school_file_contents`: بايتات الملفات الجديدة عند تشغيل التخزين داخل Neon.

ليست هذه النسخة تطبيقًا حرفيًا لقائمة الجداول المنفصلة الطويلة في المواصفات؛ تستخدم نموذج سجلات مترابطة. تحويل المجالات إلى جداول مستقلة يحتاج ترحيلًا إضافيًا إذا كان مطلوبًا.

## النشر

الواجهة والخادم يعملان في المعاينة الحالية. لم يُنشر المشروع ولم يُختبر موقع إنتاج.

أُضيفت إعدادات Render وVercel وترحيلات Neon وتهيئة اللغات والمستويات.
الدليل الكامل في `docs/deployment.html`، مع أوامر البناء والتشغيل والمتغيرات المطلوبة.
لم يحدث اتصال بقاعدة Neon فعلية أو نشر خارجي بعد؛ سيضع المالك الرابط والمفاتيح في إعدادات الاستضافة.
خارج Replit تحفظ الملفات الجديدة في Neon. ملفات Replit القديمة وحسابات مزود المصادقة القديم لا تُنسخ تلقائيًا.
عند إعادة النشر على Render تظهر المسارات الداخلية تحت `/api/auth`; أعد النشر بعد تغيّر backend قبل اختبار دخول Vercel.

## النسخ الاحتياطي والاستعادة

لم يُفعّل جدول نسخ احتياطي مخصص ولم تُختبر الاستعادة.
قبل الاستعمال الفعلي يجب اعتماد سياسة للنسخ والاستبقاء واختبار استعادة في قاعدة منفصلة؛ لا تختبر الاستعادة فوق قاعدة المدرسة.

لبيئة PostgreSQL خارجية يملكها المستخدم يمكن للمشغّل استخدام `pg_dump` بتنسيق custom و`pg_restore` إلى قاعدة اختبار مع بيانات الاتصال من إعدادات آمنة، ثم مقارنة أعداد السجلات والعلاقات والملفات. لا تحفظ النسخ داخل Git أو مجلد عام.

## أمور تحتاج اختبارًا فعليًا قبل القبول

- إنشاء الطالب بكل تسجيلاته عبر المتصفح بعد تهيئة المدير.
- دعوة الأستاذ والطالب، قبول الدعوة، واستعادة كلمة المرور.
- رفع صورة وملف حقيقيين والتحقق من بقائهما بعد الدخول مجددًا.
- تأكيد ورفض دفع حقيقي في بيئة اختبار مع التحقق من عدم التكرار.
- الرحلات الكاملة للأستاذ والطالب وصلاحيات موظف إداري.
- تغيير الجداول والتعارضات تحت طلبات متزامنة.
- الاختبارات المتقدمة ومحاولاتها المتعددة، والوحدات الدراسية المنفصلة.
- بطاقات التقارير التحليلية التفصيلية؛ الموجود الآن ملخصات فعلية وتصدير سجلات CSV مفلترة.

بوابة الدفع الإلكتروني غير مربوطة؛ الموجود دفع يدوي فقط. الإجابة الصوتية تدعم رفع ملف صوتي، وليس التسجيل المباشر من الميكروفون.
